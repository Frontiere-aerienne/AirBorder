# Journey progress integration

The browser overlay connects to authenticated GET/POST `/v1/journeys/{trip}/{leg}`. The Cloudflare Worker verifies the existing Access JWT and rate limit, hashes its authenticated subject, and selects a Durable Object from subject + trip + leg. Caller-supplied ownership cannot select another passenger's storage. Each commit atomically saves a snapshot, increasing revision and idempotency record. Reusing an event ID with a changed payload fails. Conditional not-needed values and all step IDs are validated; confirmations never change route timing, entry eligibility or selected stops.

Deploy the combined API with `npx --prefix Backend wrangler deploy --config Web/wrangler.toml` after setting real Cloudflare Access issuer/audience, explicit allowed origin, and account bindings. The SQLite Durable Object migration is included. The deploy dry run is verified; the service has not been deployed by this change. Do not deploy the placeholder Access settings. Prefer a same-origin authenticated proxy for the browser: no JWT or provider secret belongs in JavaScript. The existing remote API deployment does not acquire these capabilities until updated.

Before loading app.js, the authenticated host supplies `window.AIRBORDER_JOURNEY = {trip: 'opaque-trip-id', leg: 'opaque-flight-leg-id'}` and, if needed, `window.AIRBORDER_API_BASE`. IDs must refer to the actual dated itinerary; never use a shared constant for all trips. The fixture app intentionally retains session-local saving until this binding exists. Browser sync uses same-origin credentials. Cross-origin account sign-in is not implemented by the public directory preview.

The client stores an owner/URL-scoped outbox in sessionStorage, retries identical events on reconnect, and blocks on revision conflict. The checklist offers Use saved progress for an explicit conflict resolution; this discards queued local changes. Dispatch `airborder:logout` when the host signs out to clear progress and its active outbox. An in-flight response cannot restore logged-out progress. A closed browser session does not retain the outbox; acknowledged server progress persists. Durable records currently accept at most 1,000 events and then return an explicit error. Automated retention/deletion, persistent offline outboxes, itinerary reconciliation and production identity-host integration remain pending; do not claim these are deployed or fully supported.

Verification combines authenticated API/storage tests, client offline/conflict/logout tests and a browser test through the overlay's HTTP contract. Source guidance remains in journey-advice-sources.md. No live entry rules, queues or location are inferred from this service.
